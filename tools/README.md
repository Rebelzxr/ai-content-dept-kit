# tools — slide and cover renderers

Two small Python scripts that turn a JSON or a few words into finished images. They write HTML and let headless Chrome take the screenshot.

| Script | Makes | Size |
|---|---|---|
| `gui_frames.py` | Instagram / LinkedIn carousel slides + a PDF of the whole deck | 1080×1350 per slide |
| `article_cover.py` | X Article header with a title over RISO art, plus an optional code card | 1500×600 (code card 1200 wide) |

## Setup

- Python 3.9 or newer
- `pip install pillow numpy`
- Google Chrome. Default path is the macOS one. Anywhere else, set `CHROME_PATH`:
  - Linux example: `export CHROME_PATH=/usr/bin/google-chrome`
  - Windows example: `set CHROME_PATH=C:\Program Files\Google\Chrome\Application\chrome.exe`
- Internet access for fonts (Noto Sans SC, Inter, JetBrains Mono, IBM Plex Mono load from Google Fonts).
  **Offline?** Download those four families from Google Fonts, install them on your computer (or keep them in a `fonts/`
  folder and install from there), and the pages will use the installed copies.

We tested on macOS only (Python 3.9.6, Chrome). Other systems should work with `CHROME_PATH` set, but we have not tried them.

## Carousel slides

Run from the kit folder:

```bash
python3 tools/gui_frames.py examples/slides.sample.json examples/output
```

Output: `examples/output/01.png … 07.png` and `examples/output/carousel.sample.pdf`.
Leave out the second argument and the slides go into a folder named after the spec, next to it
(`slides.json` → `slides/` + `carousel.pdf`).

### Spec format

```json
{
  "id": "MY-POST",
  "lang": "en",
  "kicker": "SMALL LABEL AT THE TOP",
  "brand": "YOUR NAME · your-site.com",
  "footer": "text at the bottom right",
  "slides": [ { "type": "cover", "art": "G02", "hook": "Headline", "sub": "Subline" } ]
}
```

- `lang`: leave it out for Chinese (Noto Sans SC). Use `"en"` for English (Inter first).
- `brand`: footer left. Default is `DAINER.AI · dainer-ai.biz` — change it to yours.

Slide types:

| type | fields | notes |
|---|---|---|
| `cover` | `art`, `hook`, `sub` | uses `art/<art>-RISO.png` |
| `text` | `title`, `items[]`, `note?`, `spot?`, `spot_size?` | numbered list; `spot` = `art/spots/<name>_cut.png` |
| `window` | `title`, `sub?`, `win`, `device?`, `note?`, `win_top?` | a terminal or editor window; with `device` (`laptop`, `phone`, `monitor`) it is pasted onto the green screen of `art/devices/<device>.png` |
| `image` | `title`, `sub?`, `src`, `note?` | a real image, path relative to the spec |
| `end` | `title`, `items[]`, `cta`, `spot?` | closing slide |

`win` = `{"kind": "terminal" | "editor", "title": "...", "lines": [[style, text], ...]}`
Line styles: `cmd` (prompt line, shown with `$`), `out`, `dim`, `ok`, `bad`, `hl` (highlighted), `code`.

**Checked before rendering** (the script stops with an error otherwise):

- `win_top` is a whole number from 0 to 1350; `spot_size` from 80 to 600.
- `art` and `spot` names use only letters, digits, `_` and `-`. `device` is `laptop`, `phone` or `monitor`.
- `src` must stay inside the spec's folder (or the kit's `art/`). `../`, absolute paths and symlinks that point elsewhere are refused.
- Every page carries a Content-Security-Policy: no scripts, no frames, no network except Google Fonts.
- Temporary HTML and images go to a system temp folder, never into your output folder.

Run `python3 tools/test_security.py -v` to check these on your machine.

**The one rule:** only put commands and outputs in a window that really ran. Write in the slide note when it ran and on which version.
A screenshot of something that never ran is the easiest mistake to make and the hardest for readers to spot.

## Article cover

```bash
python3 tools/article_cover.py G02 examples/output "KICKER" "Title line 1" "Title line 2" "series name" templates/SAFETY_SETTINGS.json
```

Output: `examples/output/cover.png` and (because a code file was given) `examples/output/code.png`.
The code card is a fallback image for editors that break code-block formatting.

Environment options: `KIT_BRAND` (default `DAINER.AI`), `CODE_LABEL` (default `.claude/settings.json`), `CHROME_PATH`.

## Art included

`art/` holds RISO-style images generated by DAINER.AI with an AI image model, all text-free:

- `art/G02-RISO.png` — cover art (portrait, subject in the lower part)
- `art/spots/*_cut.png` — square spot illustrations: checklist, gates, magnifier, notebook, sorting, stamp
- `art/devices/*.png` — laptop, monitor, phone with a pure green (#00FF00) screen for `device` slides

To add your own cover art: save it as `art/<ID>-RISO.png` and use `"art": "<ID>"`.
For device art: the screen must be one clean rectangle of pure green; the script finds it automatically.

The G02 image carries its original C2PA "content credentials" metadata, which marks it as AI-generated. We left it in on purpose.
